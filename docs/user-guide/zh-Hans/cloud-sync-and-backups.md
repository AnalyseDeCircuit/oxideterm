# 云同步与备份

使用云同步在设备之间共享选定的配置。需要独立备份或一次性迁移时，可以导出加密的 `.oxide` 文件。

## 云同步状态

打开云同步页面，查看同步是否已配置、上次运行时间，以及本地或远端状态是否需要处理。改变同步方向前，先在应用里查看状态和警告。

点击同步可合并两端的独立修改；同一项内容发生冲突时，在预览中选择要保留的版本。

## 配置同步

### 第一台设备

1. 打开“云同步 → 配置”，选择远程存储后端。“本地文件”用于手动导入导出，不会自动连接其他设备。
2. 填写存储位置和认证信息，确保需要接入的设备都能访问该位置。
3. 为这组设备填写命名空间、文件夹路径或对象前缀，并设置加密共享数据所用的“同步密码”。第二台设备也需要这个密码；它与存储服务的登录密码或访问令牌不同。
4. 选择要同步的连接、已保存转发、快捷命令、各类连接配置、应用设置或插件设置，并检查所选设置分组。本地终端环境变量和敏感凭据需要单独开启。
5. 点击“保存设置”。先完成一次手动同步，再考虑启用自动上传。
6. 点击“同步”，检查“同步预览”，然后点击“应用并同步”。远程位置为空时，这会发布所选的本地配置。
7. 在“概览”查看结果和最近同步时间。首次创建 GitHub Gist 时，记下生成的 Gist ID，供下一台设备使用。

不同后端需要填写的位置如下：

| 后端 | 两台设备应使用的位置 |
| --- | --- |
| WebDAV | 端点和命名空间 |
| S3 兼容存储 | 服务端点、存储桶、区域和对象前缀 |
| Git 仓库 | 仓库、分支和命名空间 |
| GitHub Gist | 同一个 Gist ID 和命名空间；ID 留空时可在首次发布时创建私有 Gist |
| Dropbox | 账号和文件夹路径 |
| OneDrive / Google Drive | 账号和配置的同步文件夹或命名空间 |
| HTTP JSON | 支持 OxideTerm 当前同步协议的服务器、端点和命名空间 |

密码和令牌填写在对应的凭据字段中。未启用敏感凭据同步时，连接密码、密钥口令、托管私钥、AI 密钥和提权凭据均被排除。需要共享时，为所选数据开启“同步敏感凭据”，并确认应用提示。

### 接入第二台设备

1. 安装支持同一云同步格式的版本。
2. 打开“云同步 → 配置”，选择相同后端和存储位置，包括对应的命名空间、分支、存储桶或 Gist ID。
3. 在此设备上登录存储服务，填写与第一台设备相同的同步密码，选择需要的数据并保存设置。
4. 点击“同步”并检查预览；第二台设备已有连接或设置时，尤其要检查这些内容的变化。
5. 为冲突选择要保留的版本，然后点击“应用并同步”。检查导入的连接和设置，并试连一台主机。
6. 若未同步凭据，在第二台设备补充认证信息。第一台设备上的密钥文件路径也可能需要改为当前设备可用的路径。

手动同步成功后可启用自动上传。互不冲突的修改会合并，有冲突的修改会保留供选择。取消某类数据的同步只会将它排除在当前设备的同步范围外，不会删除远程数据。

## 冲突与中断恢复

预览列出发生变化的字段和各个候选版本。逐项选择需要保留的版本，“当前设备”标出本地版本；凭据等内容显示为“受保护的内容”。未选择的冲突保留当前本地值，并继续等待处理。“应用并同步”会保存所选结果并发布到共享位置，其他设备再次同步后才能收到。

远程预览加载期间发生的本地编辑也会纳入合并；应用后如仍有冲突，请继续检查。

| 提示或现象 | 处理方法 |
| --- | --- |
| 认证失败或无法访问存储 | 检查服务登录、端点以及文件夹、存储桶或仓库权限，保存后重试 |
| 无法解密共享数据 | 确认存储位置和同步密码与另一台设备一致 |
| 本地修改已应用，但上传失败 | 保留当前配置，再次同步以重试发布 |
| 等待清理 | 再次同步以完成清理 |
| 应用数据时同步中断 | 重新打开 OxideTerm，让应用恢复未完成的操作，再重试同步 |
| HTTP JSON 服务器需要升级 | 先将该服务器升级到支持当前协议的版本 |

恢复仍失败时，保留当前数据目录并记录错误，不要通过删除恢复文件绕过检查。需要从命令行恢复时，先关闭桌面应用，再运行 `oxideterm cloud-sync sync --yes`；该命令除了恢复中断操作，还可能应用和发布同步修改。

## 更改同步密码

在云同步设置中输入新密码并保存，确认后会创建新的同步空间。上传并校验成功后，应用切换到新空间；原空间和数据会保留。其他设备需要填写新的命名空间和密码。

如果上传失败，重新提交同一新密码可以继续上次的变更。

修改后端等其他设置时，先保存这些设置，再更改密码。CLI 可使用 `oxideterm cloud-sync change-password --yes`，由密码管理器通过标准输入传入新密码。

## 备份

### `.oxide` 文件

新导出的 `.oxide` 文件会加密连接名称、数量等元数据，输入密码后才能预览内容。旧版文件仍可导入，新版文件需要使用支持新版格式的客户端读取。包含完整证书和私钥的档案会导入托管密钥存储，并保留证书认证方式和私钥口令。

### 创建备份

高影响操作前先创建备份：

- 批量导入连接。
- 导入 `.oxide` 包。
- 执行云同步应用或冲突解决。
- 迁移插件状态。
- 修改会影响终端、SSH、提权凭据、AI 或同步行为的设置。

手动创建加密备份时，在“云同步 → 配置”选择“本地文件”，设置文件密码和导出内容，保存后点击“导出到本地文件”。将文件和密码分开保管。恢复时选择“从本地文件导入”，检查预览，选择需要的数据和冲突策略，再确认导入。凭据选项见[便携包指南](portable-oxide.md)。恢复远程同步时，重新保存原远程后端配置。

如果云同步“历史”页有以前的回滚备份，选择后点击“恢复所选备份”，检查恢复预览。这会在本地应用备份中的配置；需要让其他设备收到恢复结果时，再执行同步。

命令行也能创建包含设置、连接和云同步元数据的 JSON 备份。迁移凭据仍需要加密导出。仅恢复设置时，可以按以下步骤预览和应用：

```sh
oxideterm backup create --output ./oxideterm-backup.json --json
oxideterm backup verify ./oxideterm-backup.json --json
oxideterm backup restore ./oxideterm-backup.json --section settings --dry-run --json
```

检查预演结果后，执行这次仅恢复设置的操作：

```sh
oxideterm backup restore ./oxideterm-backup.json --section settings --yes --json
```

重新打开相关设置确认结果。需要完整保存本地历史和录制时，参阅[数据目录备份](portable-oxide.md#数据目录备份)。

## 支持包

需要共享诊断信息时使用支持包。发送前先检查生成文件。它应包含路径、计数、警告、修订信息和凭据提示，而不是凭据值，提权凭据也一样。

## CLI 伴侣工具

脚本化同步、恢复计划、CI 检查或支持包使用 CLI 伴侣工具：

```sh
oxideterm cloud-sync status --json
oxideterm cloud-sync sync --dry-run --json
oxideterm cloud-sync preview --json
oxideterm cloud-sync diff --dirty-only --format table
oxideterm backup preview --json
oxideterm backup create --output ./oxideterm-backup.json --json
oxideterm report --bundle ./oxideterm-report.json --json
```

`cloud-sync sync --dry-run` 会从远程后端准备预览，不应用或发布修改。独立的 `preview` 和 `diff` 命令查看的是缓存状态。命令行同步需要独占访问配置，运行前先关闭桌面应用。

命令行写入先执行预演，确认修改符合预期后再执行：

```sh
oxideterm cloud-sync sync --yes --json
```
